# 诚实口径：哪些是真，哪些是仿真

> 目标：让这个仓库**可复现、可审查、不夸大**。算法与协议是真实实现，缺的硬件用
> 模拟件等价替代，且逐项写清楚。面试/简历引用时按这里口径说，不编数字。

## 真实实现（算法/协议/数学）

| 项 | 实现 | 验证方式 |
| --- | --- | --- |
| 相机内参标定 | 张正友标定法（cv2.calibrateCamera） | 合成投影 + 噪声，恢复 K 与真值对比（fx 误差 ~0.07%） |
| 九点标定 | 图像↔基座平面单应映射 + 残差 | 合成 9 点，残差 ~0.2mm |
| 手眼标定 | AX=XB，Tsai-Lenz 两步法（先旋转后平移） | 与 OpenCV `calibrateHandEye(Tsai)` 交叉验证一致 |
| 工件定位 | OpenCV 阈值/轮廓/最小外接矩形；YOLO 适配器 | 端到端定位误差 <0.6mm |
| 缺陷检测 | PatchCore 无监督异常检测（torch）；统计 z-score 兜底 | 正常样本训练，缺陷样本得分显著更高 |
| 传送带动态跟踪 | pulses/mm 标定 + 触发锁存 C0 + 计数差补偿 `(C1-C0)/ppm` | 补偿后定位误差 ~0.35mm |
| Modbus TCP | 真实协议栈（pymodbus），点表 + float32 字序约定 | Client↔模拟 Server 握手往返，字序/单位逐位校验 |
| MQTT 旁路 | 真实 paho-mqtt 客户端（无 broker 时用 JSONL 落盘） | — |
| 单帧节拍 | 本机实测（time.perf_counter，300 次统计） | 见 `outputs/benchmark.json` |

## 仿真替代（缺硬件）

| 项 | 真机 | 本仓库替代 |
| --- | --- | --- |
| 相机 | GigE Vision 硬触发相机 | `SimCamera`：已知单应渲染合成图 + 锁存编码器 |
| 传送带/编码器 | 增量编码器 A/B/Z，RS422 | `EncoderSim`：浮点计数，公式与真机一致 |
| PLC | 西门子/三菱等 | `PlcSim`：pymodbus 起等价 Modbus TCP Server |
| 机器人 | 六轴 + EtherCAT 伺服 | `RobotMock`：读结果 + 编码器差补偿（不做运动学/插补） |
| 工件图像 | 现场来料 | `render_scene`：合成"皮带+工件+划痕/凹坑"俯视图 |

## 数字口径（面试前逐条对齐）

- **单帧节拍**：本机实测的是 **OpenCV 经典定位路径**，mean ~3ms（见
  `outputs/benchmark.json`）。简历里 "视觉单帧 <80ms" 指的是**完整路径
  （YOLO + PatchCore）的目标值**；经典路径更快的实测结果可作为支撑口径。
  要报 80ms 这个数，先在装了 GPU/权重的环境把 YOLO+PatchCore 真测一次。
- **动态抓取成功率 99% / ±0.5mm**：本仓库给出的是**定位/补偿误差 ~0.35mm**（合成
  场景、无真实机械误差），不是产线成功率。真机口径需带"连续作业时长/人工干预次数"
  或重复测量统计，没有就别报百分比。
- **标定误差**：内参/九点/手眼都给了**数值误差**（见 `outputs/calib/calibration.json`），
  口径是"合成真值 + 加噪恢复的误差量级"，用于证明算法正确性，不代表真机标定精度。

## 别这么说（对照简历"面试注意"）

- ❌ "相机真机取图已跑通" → 本仓库相机图像是**合成渲染**，未接真机 GigE Vision SDK。
- ❌ "孪生控制机器人" → 孪生是**旁路只读镜像**，只写文件/MQTT，不写任何设备。
- ❌ "自研手眼标定库" → 手眼标定**自实现 Tsai-Lenz 并与 OpenCV 交叉验证**；产线用
  easy_handeye2 这类现成库也如实说。
- ❌ "训练了 PatchCore 到量产" → 这里 PatchCore 是**代码实现 + 合成数据演示**，
  未在真实缺陷样本上训练/调阈值。
